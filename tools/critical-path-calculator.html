Questions this page answers

What is the critical path of a project?

The critical path is the longest chain of dependent tasks in the plan, and its length sets the project finish date. Every task on it has zero total float: if a critical task slips by a day, the delivery date moves by a day. Tasks off the chain have float, so a small delay there does not move the end date.

What is float (slack) and how is it calculated?

Total float is the number of days a task can slip without moving the project finish date. It is latest start minus earliest start (or latest finish minus earliest finish, which is the same number). Earliest values come from a forward pass through the dependency graph; latest values come from a backward pass from the project end. Zero float means the task is on the critical path.

How the critical path method works

The critical path method (CPM) is a scheduling algorithm that turns a list of tasks, durations and dependencies into dates — and, more importantly, into an explanation of which tasks actually decide the finish date. A critical path calculator like this one automates the arithmetic, but the algorithm is small enough to do by hand, and knowing what it does makes the output readable.

The first step is the forward pass. Walking through the tasks in dependency order, each task's earliest start (ES) is the latest earliest finish (EF) among its predecessors — you cannot begin until all of them are done. Its earliest finish is then simply ES plus its duration. Tasks with no dependencies start at day 0. When the forward pass is done, the largest earliest finish in the plan is the earliest possible project finish.

The second step is the backward pass, which runs in the opposite direction. Starting from that project finish, every task's latest finish (LF) is the earliest latest start (LS) among its successors — if a successor must begin by day 10, you must be finished by day 10. Its latest start is LF minus duration. Tasks with no successors get the project finish date as their latest finish.

With both passes done, the total float of each task falls out immediately: LS minus ES. A task with three days of float can slip three days without anyone noticing on the delivery date. A task with zero float cannot move at all without moving the project end — and the chain of zero-float tasks from start to finish is the critical path. This calculator highlights that chain in red on the Gantt chart, which is usually the only part of the plan worth watching in a weekly review.

Three things the textbook algorithm does not model, and neither does this page: working calendars (a five-day week with weekends off), overlapping dependencies (start-to-start or finish-to-finish links), and resource limits (two people who cannot both do two full-time tasks). Small plans tolerate those simplifications; real ones usually do not, which is why a spreadsheet CPM calculation eventually stops matching reality.
