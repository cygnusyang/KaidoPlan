Release · v3.4.0

v3.4.0 — 2026-11-07

Connecting an agent stopped being a copy-and-paste exercise, and the app became its own MCP server.

Updated 2026-11-08 · by cygnus, the developer of KaidoPlan

This is the permanent page for v3.4.0. It is also the current public release.

Added

  • One switch per MCP client. Claude Desktop, Claude Code, Cursor, Codex and WorkBuddy. The writer is text-level and preserving: it adds or removes only mcpServers.kaidoplan (Codex uses [mcp_servers.kaidoplan]) and leaves the rest of the file untouched, including CRLF line endings.
  • Visible per-client state. Connected, configuration needs updating (the endpoint or token in the config no longer matches), write failed with a reason and a retry, not connected, client not installed.
  • --mcp-stdio mode. The app's own executable can be launched by a client as a stdio MCP server. The mode is intercepted early in launch, so no window appears and no Dock icon is added.

Changed

  • MCP service on by default. The default flipped from off to on; an existing installation that had explicitly turned it off stays off, because only the default changed.
  • Port persistence. The first successful bind is stored and preferred on restart, falling back through 56 private ports when it is taken. The stored preference is not overwritten by a fallback.
  • Panel redesign. The old "copy this JSON yourself" block became the per-client switch list. A copy-configuration button remains as the manual path.

Notes

The service listens on the loopback address only, requires the token shown in the panel, and can reach only folders authorized there. Write tools remain gated by the Pro licence after the 30-day trial; a refusal happens before anything is written to disk.
