Baselines and variance

Without a frozen schedule, it slipped is an opinion. A baseline turns it into two numbers.

Updated 2026-11-08 · by cygnus, the developer of KaidoPlan

The tools

ToolDoes
baseline_createTakes an immutable snapshot: planned start and finish plus completion state are frozen. Returns the baseline's id, name, colour and entry count.
baseline_listLists baselines in creation order, oldest first.
baseline_varianceCompares both the current plan and the actual dates against a baseline. Omitting the id uses the most recent one.
baseline_deleteRemoves one baseline; the tasks are untouched.
baseline_set_colorChanges the palette colour of a baseline. Only the colour — the snapshot entries and creation time do not move.

Two comparisons, not one

Planned-versus-baseline tells you the schedule changed. Actual-versus-baseline tells you the work took longer than promised. They are different facts and they lead to different conversations: the first is usually a scope or dependency decision, the second is an estimate problem.

kaidoplan baseline create --file plan.kaido
kaidoplan baseline variance --file plan.kaido

When to take one

  • At the start of each reporting period, so the report has a reference point.
  • Before a delivery push, so the promise has a frozen state behind it.
  • Before a large re-plan, so the cost of the re-plan is measurable afterwards.

Immutability is the feature

A snapshot you can edit is a rumour. These entries are frozen at creation, which is why a baseline from three weeks ago still means what it meant then.

Questions this page does not answer

Can I recover an old plan from a baseline?

A baseline records the planned dates at that moment; it is a reference, not a backup. Use the repository or your backup for restoration.

How many baselines can I keep?

They are cheap and listed in creation order. Keep the ones whose comparison you would actually make.
