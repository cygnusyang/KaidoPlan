Status write-back

The difference between an agent that reports progress and one that records it: a completion time that a conflict check can use.

Updated 2026-11-08 · by cygnus, the developer of KaidoPlan

The tools

ToolDoes
status_updateWrites status and progress for one task. Setting a task done records the completion time.
status_batch_updateWrites many entries at once and returns per-entry success and failure. A failing entry does not stop the remaining ones.

Completion time is the point

"Done" as a boolean is enough for a burndown and useless for a schedule. The date a task actually finished is what determines whether the task that depended on it started too early — which is the most common real cause of a slipped date in an agent-driven project.

kaidoplan status batch --file plan.kaido --json

Partial success looks like success

Bulk writes deliberately do not abort on the first failure. That is the right behaviour for a long list, and it means the response has to be read: nine of ten entries landing is a state you want to know about, not a state to infer.

Write access is a paid feature

On the free tier an agent can read the plan but not change it. Write-back requires Pro ($9.99/year). The split is not about monetising a checkbox: an agent with write access changes delivery dates, and the point of the free tier is that read-only is genuinely useful.

The loop to run

  1. The agent writes status through the tools, not through prose.
  2. The schedule is recomputed.
  3. Violations are listed.
  4. Any new conflict gets a decision before the next task starts.

Skip step 2 and the plan accumulates contradictions that only surface when a client asks for a date.

Questions this page does not answer

Does it save automatically?

Write operations save the session's file when there are unsaved changes, so a client does not have to call a save tool after every update.

Can I reject a write?

You control the tool surface: an agent only has the access you granted. Turning the MCP service off stops writes immediately.
