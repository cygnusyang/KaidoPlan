The command line

Everything the app can do to the plan, from a terminal — which is also the shortest path to putting a schedule check in CI.

Updated 2026-11-08 · by cygnus, the developer of KaidoPlan

The command surface

kaidoplan project create|open|save|summary
kaidoplan task add|list|get|update|delete
kaidoplan wbs import
kaidoplan schedule compute|path
kaidoplan violations
kaidoplan status update|batch
kaidoplan resource add|list
kaidoplan baseline create|list|delete|color|variance

Every command takes --file; JSON output is available where a script needs structure rather than formatted text. The CLI works whether or not the app is open — it opens the file, performs the operation and saves.

The four commands worth memorising

kaidoplan schedule compute --file plan.kaido   # dates from the graph
kaidoplan schedule path --file plan.kaido      # the chain that sets the date
kaidoplan violations --file plan.kaido         # what the plan admits is broken
kaidoplan status batch --file plan.kaido       # write progress back, per-entry

Why a CLI and not only an MCP server

The MCP server needs the app and a client. A shell command needs neither, which makes it the option that survives in scripts, in CI and in a shell history you can read six months later. The two surfaces are the same operations on the same file, so choosing one is not choosing a different feature set.

Putting it in CI

A dependency cycle can be made a build failure in one line. That is a cheap guarantee: it means no commit can introduce a plan that can never start, and it costs nothing when the check passes.

Questions this page does not answer

Does the CLI need a licence?

Reading, scheduling and checking are read operations and work on the free tier. Write operations from other tools follow the same Pro boundary as the MCP server.

Can I use it without the app installed?

The CLI is a separate Homebrew package. Whether it needs the app's licence state depends on the operation — reads do not.
