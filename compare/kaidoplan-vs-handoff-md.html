KaidoPlan vs a HANDOFF.md file

A handoff file is the cheapest coordination mechanism that works. It is also the reason nobody notices the schedule has stopped adding up.

Updated 2026-11-08 · by cygnus, the developer of KaidoPlan

What a handoff file does well

A HANDOFF.md — or CLAUDE.md, or an AGENTS.md — is a plain file in the repository that tells the next session what is going on: what was finished, what is next, which decisions are settled. It costs nothing, it diffs, it survives tool changes, and every agent can read it. If the only problem you have is "the agent forgot what we did yesterday", a handoff file solves it and nothing else is needed.

What it cannot do

HANDOFF.mdKaidoPlan
ShapeProse, written by whoever updated it lastStructured plan: tasks, groups, milestones, effort, dependencies
DatesWhatever the text saysComputed from dependencies, constraints and a project window
Critical pathNot representableComputed, with per-task slack
ConsistencyContradictions are prose contradictions — nobody diffs themViolations are listed: cycles, deadline conflicts, out-of-window tasks
HistoryGit history of a narrativeBaselines: immutable schedule snapshots you can compare actuals against
CostFree, zero setupA macOS app, a file format, and ten minutes of setup

The failure is structural rather than a matter of discipline. Prose has no edges, so nothing prevents a handoff file from saying "client integration starts 11-04" in one paragraph and "server implementation ends 11-06" in another. Both sentences are true to their author, and the plan they describe cannot happen. A graph makes that contradiction a violation you can list.

The overlap people miss

A handoff file is good at intent, and a plan is good at arithmetic. The mistake is asking one to do the other: a plan file full of design rationale is as unreadable as a WBS written in paragraphs. Keep the reasoning in HANDOFF.md, keep the dates and dependencies in the plan, and let the agent read both. KaidoPlan's plan is plain JSON, so an agent that can read a markdown file can read this one too — 21 MCP tools cover reading and writing it, and the CLI does the same from a shell.

When the handoff file wins

  • One person, one week, no external deadline. There is nothing to compute.
  • The work is genuinely exploratory: you do not know the tasks yet, so a WBS would be fiction with dates attached.
  • You are on Linux or Windows, where KaidoPlan does not run.

If two of those three are false, the handoff file is carrying a schedule it cannot represent — and the first time you need to answer "can we still ship on the 21st" it will answer with a paragraph instead of a number.

Questions this page does not answer

Can the agent update both?

Yes. The plan is a local JSON file with a documented schema and an MCP surface; the handoff file is markdown. An agent can be told to keep dates in the plan and reasoning in the handoff file, which is usually the cleanest split.

Is a plan file still readable in a pull request?

It diffs as JSON. A date change is a one-line diff, which is more reviewable than the same change described in a paragraph.
