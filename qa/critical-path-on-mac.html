How do I calculate a critical path on a Mac?

Use a tool that reads the dependency graph and recomputes the chain whenever a date changes. On macOS that means three options: a planner built around dependencies, a general project management app, or a spreadsheet. Only the first one keeps the answer correct after the third edit.

Updated 2026-11-17 · by cygnus, the developer of KaidoPlan

The three options on macOS

  • A planner that computes the chain itself. You enter tasks, durations and dependencies; the tool runs a forward and backward pass and highlights the zero-slack chain. The answer updates when any input changes.
  • A general project management app. Many of them compute a critical path. They are built around team collaboration and boards, so the dependency editor is usually a secondary screen and the schedule is derived from assignments rather than from the graph.
  • A spreadsheet. Free, and correct for a plan with a handful of tasks and a single chain. It stops being correct as soon as the graph branches, because you have to describe the calculation in formulas and keep them in a valid order.

There is no macOS-specific algorithm here. The calculation is the same on every platform. What differs on a Mac is where the plan lives and who can read it, which matters more than it sounds when AI agents are part of the work.

Doing it by hand, and where it breaks

The manual version is two passes over the graph:

  1. Forward pass. For each task in dependency order, earliest start is the latest earliest finish among its predecessors; earliest finish is earliest start plus duration.
  2. Backward pass. From the project end backwards, latest finish is the earliest latest start among its successors; latest start is latest finish minus duration.
  3. Slack. Latest start minus earliest start. Zero means the task is on the critical path.

This is correct and it is also where most hand calculations go wrong, in three specific ways:

  • Order matters and is invisible in a spreadsheet. A row that reads a value not yet recalculated returns a stale number, quietly. The error shows up as a plausible plan, not as an error.
  • A task with two successors needs the minimum, not the first one you look at. Missing the second successor makes a critical task look slack.
  • Constraints are not part of the textbook algorithm. A fixed delivery date, a task that cannot start before a date, or a calendar with non-working days has to be folded in, and a spreadsheet has no place to put it.

You can run both passes on your own numbers in the free online critical path calculator — it shows ES, EF, LS, LF and total float for every task and highlights the zero-slack chain in red on the chart.

Running it locally on a Mac

KaidoPlan is a macOS app that keeps the WBS, the dependency edges and the dates in one local .kaido file — plain JSON, no database, no account. The schedule engine computes the critical path, total and free slack, and reports violations: date conflicts, dependency cycles and tasks scheduled outside their allowed window.

The same calculation is available without opening a window:

kaidoplan schedule path --file plan.kaido

The CLI and the MCP server are the same engine the app uses, so a command-line answer and the highlighted chain in the Gantt chart cannot disagree. Both are read-only without a licence; writing task status, actual dates or new tasks back into the plan needs Pro.

Why "on a Mac" changes the answer

For a local-first tool the platform question is mostly a data question. Three consequences that do not apply to a web planner:

  • The file is yours. A .kaido plan can be diffed, reviewed in a pull request, or kept next to the code it describes. There is no export step and no vendor copy of the schedule.
  • Agents read the same file. Claude Code, Codex and other MCP clients read the plan through stdio; the plan does not have to be synchronised into a service first.
  • No connection, no account. The 30-day trial requires neither. When it ends the app drops to the free tier — the whole planning workbench, AI read-only, and three delivery-report exports a month — it does not stop.

The trade-off is stated plainly on the product page: this is a single-user local tool. There is no real-time multi-user editing, no cloud sync, and no Windows or Linux build. Sharing a plan with another person means sending the file.

Questions this page does not answer

Can I calculate a critical path in a spreadsheet on a Mac?

Yes, for a small plan and with care. You do a forward pass for earliest start and finish, a backward pass for latest start and finish, then subtract. It breaks down once a task has more than one successor, or when a calendar or a fixed deadline enters the model, because a spreadsheet recalculates rows in an order you did not choose.

Does the calculation need a cloud account on macOS?

Not with KaidoPlan. The plan is one local .kaido JSON file and the schedule is computed in the app on the machine. There is no account and nothing is uploaded, so the file can live in a git repository or iCloud Drive without sending the plan to a third party.

Can an AI agent read the critical path on a Mac?

Yes, read-only and without a licence. The CLI and the MCP server expose 21 tools over stdio JSON-RPC, and reading plans is free. Writing task status, actual dates or new tasks back into the plan needs a Pro licence.
