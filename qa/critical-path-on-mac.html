How do I calculate a critical path on a Mac?

The algorithm is the same on every platform: a forward pass, a backward pass, and the zero-slack chain that comes out of the difference. What differs on a Mac is where the plan lives and whether an agent can read it — which decides how often the number is still correct.

Updated 2026-11-17 · by cygnus, the developer of KaidoPlan

What you are actually choosing between

There is no macOS-specific critical path method. Earliest start, earliest finish, latest start, latest finish, slack — that arithmetic was settled before personal computers existed, and a Mac computes it no differently from anything else.

So the real question is not "which app has the algorithm". It is "which setup still gives the right answer after the third edit, when a task duration changed and two dependencies moved". That is a data-model question, and on macOS it has three answers with very different failure modes.

Doing the two passes by hand

Worth knowing even if you never do it by hand, because it tells you what to distrust in any tool's output:

  1. Forward pass. In dependency order, earliest start is the latest earliest finish among predecessors; earliest finish is earliest start plus duration.
  2. Backward pass. From the project end, latest finish is the earliest latest start among successors; latest start is latest finish minus duration.
  3. Slack. Latest start minus earliest start. Zero means the task sets the end date.

The calculation is four lines. The errors are not in the calculation.

Why a spreadsheet is right until it is silently wrong

Take three tasks: Schema (2 days), Migration (3 days, depends on Schema), Backfill (1 day, depends on Migration). Row 2 reads row 1, row 3 reads row 2. Change Schema from 2 to 4 and a spreadsheet either recalculates in the right order or it does not — and if it does not, the cell shows a number that is plausible, not an error.

Three specific traps, all of which produce a believable plan rather than a broken one:

  • Recalculation order is invisible. A cell that reads a value not yet recomputed returns the old value. There is no warning, because a stale number is a number.
  • Two successors need a MIN, not the first one you looked at. Miss the second successor and a task on the critical path reports positive slack — the most expensive possible mistake, because it is the one that makes a late project look safe.
  • Constraints are outside the textbook algorithm. A fixed demo date, a reviewer who is away until the 12th, a calendar with non-working days: each has to be folded in by hand, and a spreadsheet has no column that means "this edge cannot start before a date".

If you want to see the two passes run on your own numbers without building the formulas, the browser calculator shows ES, EF, LS, LF and total float per task and highlights the zero-slack chain. It runs locally; nothing is uploaded.

What to check before trusting any number

  • Is there an edge list, or only dates? A plan with dates and no dependencies has no critical path. It has a wish with columns.
  • Does the tool recompute, or does it store what you typed? If a duration change does not move the finish date, you are looking at a table, not a schedule.
  • Does it report conflicts? An optimistic plan can be internally inconsistent: a task finishing after its successor started. A tool that cannot name that will let you present it.
  • Can you see slack per task, not just the highlighted chain? The chain tells you what to protect today. Slack tells you where the next chain will come from.

On macOS specifically: local-first changes three things

KaidoPlan keeps the WBS, the edges and the dates in one local .kaido file — plain JSON, no database, no account. That is a platform decision with consequences that a web planner cannot offer:

  • The file is yours. It can be diffed, reviewed in a pull request, or kept next to the code it describes. There is no export step and no vendor copy of your schedule.
  • Agents read the same file. Claude Code, Cursor, Codex and other MCP clients read the plan over stdio, so the schedule does not have to be synchronised into a service before an agent can see it.
  • No connection, no account. The 30-day trial needs neither. When it ends the app drops to the free tier — the planning workbench, AI read access, and three delivery-report exports a month — rather than locking the file.

The same computation is available from a terminal, which is what makes it usable inside an agent loop:

kaidoplan schedule compute --file plan.kaido
kaidoplan schedule path --limit 2 --file plan.kaido
kaidoplan violations --file plan.kaido

schedule path returns the tasks whose total slack is within the limit, so --limit 2 answers "what has two days or less of room" rather than only naming the zero-slack chain. Reading plans and running the schedule needs no licence; writing status, actual dates or new tasks back needs Pro.

The limitation, stated plainly

This is a single-user local tool. There is no real-time multi-user editing, no cloud sync, and no Windows or Linux build. Sharing a plan with another person means sending the file. If the requirement is four people editing one schedule simultaneously, the right answer is a hosted tool, and the cost you accept is that the schedule lives in someone else's database.

Questions this page does not answer

Can I calculate a critical path in a spreadsheet on a Mac?

Yes, for a small plan and with care. You do a forward pass for earliest start and finish, a backward pass for latest start and finish, then subtract. It breaks down once a task has more than one successor, or when a calendar or a fixed deadline enters the model, because a spreadsheet recalculates rows in an order you did not choose.

Does the calculation need a cloud account on macOS?

Not with KaidoPlan. The plan is one local .kaido JSON file and the schedule is computed in the app on the machine. There is no account and nothing is uploaded, so the file can live in a git repository or iCloud Drive without sending the plan to a third party.

Can an AI agent read the critical path on a Mac?

Yes, read-only and without a licence. The CLI and the MCP server expose 21 tools over stdio JSON-RPC, and reading plans is free. Writing task status, actual dates or new tasks back into the plan needs a Pro licence.
