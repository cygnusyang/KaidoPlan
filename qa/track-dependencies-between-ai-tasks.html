How do I track dependencies between tasks an agent executes?

Record them as data, not as instructions in a prompt. A dependency in a chat message is a suggestion; a dependency in the plan is an edge the scheduler will enforce.

Updated 2026-11-08 · by cygnus, the developer of KaidoPlan

Two kinds of dependency, one place to keep them

Hard dependencies are structural: the acceptance test cannot run before the endpoint exists. Constraints are calendar facts: the security review cannot start before the 12th because the reviewer is away. Both affect the schedule, and both belong in the plan.

KindExampleWhat it changes
Finish-to-startClient integration starts when the server task endsPropagates dates; creates the chain
LagTwo days of review after the buildAdds duration to the edge rather than the task
Start no earlier thanA review that cannot begin before a dateDelays the task; can push the end date
Finish no later thanA demo that cannot slipCreates a deadline conflict when violated

Why prompts are the wrong storage

Telling an agent "do the API first, then the client" works for one session. It does not survive the session, it cannot be checked, and it silently disappears when the conversation is summarised. A dependency stored in the plan survives everything, and — the part that matters — the scheduler can prove that the resulting dates are consistent with it.

kaidoplan task update --file plan.kaido
kaidoplan schedule compute --file plan.kaido
kaidoplan violations --file plan.kaido

After the edges are in, a cycle is reported rather than discovered later, and a task scheduled before its predecessor ends is a violation instead of a surprise.

Practical discipline

  • One edge, one reason. If you cannot state why the dependency exists, delete it. Invented edges make the critical path fiction.
  • Do not model "related to". Undirected relations are not dependencies and add noise to the schedule.
  • Re-check after parallelisation. Splitting work changes the graph; the critical path you knew last week may no longer be the constraint.
  • Keep the graph in the repository. The plan is a file, so the dependency structure is reviewable in a diff — which is the only way a second person can audit it.

Questions this page does not answer

Can an agent add dependencies itself?

Yes, through the write tools, on a Pro licence after the trial. Whether it should is a policy question: edges change the delivery date, so many teams keep them human-owned.

What happens if I create a loop?

The schedule cannot be computed, and the cycle is reported as a violation. That is the correct failure: a loop means a piece of work can never start.
