Is there an MCP server for a project plan?

Yes — KaidoPlan has one built in. 21 tools over stdio or a loopback HTTP endpoint, covering tasks, dependencies, resources, baselines, scheduling and violation checks.

Updated 2026-11-08 · by cygnus, the developer of KaidoPlan

What the server exposes

The plan is a local file; the MCP server is a second surface on the same data, so an agent can ask questions and make changes without parsing JSON by hand.

GroupToolsWhat it is for
Projectproject_create, project_open, project_saveOpen the plan, create one, save it back to disk
Tasks and WBStask_add, task_list, task_get, task_update, task_delete, wbs_importRead and change the structure
Schedulingschedule_compute, schedule_critical_pathTurn dependencies into dates and slack
Violationsviolations_listCycles, deadline conflicts, out-of-window tasks

Baselinesbaseline_create, baseline_list, baseline_delete, baseline_variance, baseline_set_colorFreeze a schedule, then compare plan and actuals

Twenty-one tools in total. Client setup is one switch per client — Claude Desktop, Claude Code, Cursor, Codex and WorkBuddy — and the switch writes only the mcpServers.kaidoplan key, leaving the rest of the configuration untouched.

The security model, in three lines

  • Loopback only: the endpoint listens on 127.0.0.1, never the LAN or the internet.
  • Every request carries a token the app generates locally and shows in its panel.
  • Only folders you authorized in that panel are reachable; anything else is refused.

Read versus write

On the free tier an agent can read the plan and answer questions about it. Writing — status, actual dates, new tasks — is the Pro feature. That split is deliberate: read-only agents are useful and safe; an agent with unlimited write access changes a delivery date without anyone reviewing it.

If you would rather not add an MCP client, the CLI exposes the same operations from a shell, and the file itself is readable JSON.

Questions this page does not answer

Does it work with a remote or hosted agent?

No. The endpoint is loopback-only by design, so the agent has to run on the same Mac.

Is the server on by default?

Yes since v3.4.0, on 127.0.0.1 with a token. Turning it off in the panel stops access immediately; a previous explicit off setting is not overridden by the default change.
